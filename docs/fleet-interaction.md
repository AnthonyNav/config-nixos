# Fleet keyboard and desktop interaction

The public action catalogue is `dotfiles/fleet/actions.json`. `fleet-shortcuts`
and the visible desktop menus read it; [the shortcut guide](fleet-shortcuts.md)
is generated by `scripts/fleet-catalog.py`. Regenerate that guide whenever the
catalogue changes. CI rejects a stale guide.

Command remains native on Mac. Linux adds Super aliases for supported
applications alongside their existing Ctrl shortcuts. Caps Lock and AltGr are
not remapped. Unknown applications retain their controls. The desktop menu uses
Command+Option+Enter on Mac and Super+Alt+Enter on Linux, then single keys.
`fleet-menu` opens the same menu from a command. Native Mac application shortcuts
have priority; only known applications with a successfully inspected menu are
eligible for the global menu shortcut. VSCode on Mac retains its native
Command+Option+Enter Replace All action (including its hidden find-widget binding);
use `fleet-menu` there. Commands remain available in other apps.

## Ownership and activation

The shared Home Manager module supplies `fleet-ui`, `fleet-menu`,
`fleet-shortcuts`, the catalogue and the media helper. Platform adapters own
window and media implementations. Native apps remain under nix-darwin;
Linux physical keyboard access belongs to the NixOS system layer. No SDK,
application credential or mutable recording state belongs in the catalogue.

Develop with builds/checks on a feature branch. Never activate it. After review
and publication, activate clean main with the repository deployment workflow.
This change does not enable permissions or edit local Karabiner profiles.
Previously enabled Caps/F18 Complex Modifications must be disabled locally
before acceptance; shipping that rule stops with this change. Keep any other
user-owned Karabiner rules. Caps Lock must produce its normal state on both
integrated and external keyboards.

Mac uses Hammerspoon for menus and AeroSpace for window management. During
runtime acceptance, quit Rectangle and other window managers first. Complete
Accessibility consent for Hammerspoon and AeroSpace and Screen/System Audio
Recording consent for the invoking capture application in macOS settings.
macOS owns these permissions; builds cannot prove or grant them. In-app browser
menus and Command application commands remain native.

Linux uses Hyprland plus a user xremap service confined to the active graphical
session. Early udev uaccess rules select physical keyboards and uinput, with no
blanket input group. Physical input translation uses a GUI application allowlist
(Firefox, Thunar, DbGate); Kitty and VSCode own their contextual bindings. xremap
cannot distinguish widgets inside arbitrary apps. Its launch actions and window
logging are disabled. Virtual input from tools such as LanMouse is excluded;
do not assume it follows the physical keyboard path. Seat ACL removal cannot
revoke an already open file descriptor: validate service shutdown at logout and
session changes. Same-user processes are not isolated by these permissions.

VSCode bindings are merged into the default User profile with private ownership
state and a backup. User bindings and settings remain intact; conflicting Super
bindings must be resolved explicitly. Other Code profiles require their own
reviewed application of the helper. `fleet-editor-bindings check` reports the
merge preconditions; `apply` performs the managed merge.

## Desktop and media commands

`fleet-ui --help` lists the portable interface. `focus`, `move`, `workspace`,
`move-workspace`, `fullscreen`, `toggle-floating`, `move-mode`, `resize-mode`,
`resize-step` and `mode-exit` remain scriptable. Menus release the modifiers;
ordinary actions close the menu. Move/resize modes show an indicator and finish
with Enter/Escape. Linux captures the original window before opening its menu
and restores it before dispatch, so actions do not operate on the menu window.
The Linux mode indicator is a separate unfocused Wayland layer, not a global
notification dismissal. `fleet-ui edit ACTION` only sends a supported contextual
app shortcut. Quit requests normal application exit; it never force-kills.

```sh
fleet-ui screenshot area --clipboard
fleet-ui screenshot window --file auto
fleet-ui screenshot screen --monitor focused --file auto
fleet-ui screenshot area --region 100,100,640,480 --file auto
fleet-ui record start --target area --audio system
fleet-ui record start --target screen --audio system
fleet-ui record status
fleet-ui record stop
```

Captures are private local files under `~/Pictures/Screenshots`; recordings use
`~/Movies/ScreenRecordings`. They are outside synchronized shared directories.
Audio defaults to the system output. `--audio none` omits audio and
`--audio microphone` opts into microphone capture. An unavailable system source
is an error, never a silent fallback to microphone. An area supports interactive
selection or explicit coordinates. Monitor selection uses the focused window,
not a presumed correspondence between compositor and native display IDs.

A private supervisor owns the recording child process. Start rejects another
active Fleet recording. Stop requests are scoped to the session; the supervisor
uses SIGINT on its own child and verifies final video/audio with ffprobe. It does
not signal a PID loaded from mutable state, use killall, or force-kill a recorder.
A failed stop stays diagnosable and never claims the video is finalized.

Mac recording is gated per OS/build and recorder fingerprint. Before enabling it,
use a small public test window, play a synthetic sound through the system output,
and run `fleet-ui record probe --region X,Y,W,H`. The probe must verify SIGINT
finalization, video frames/duration and system audio before recording is enabled.
The marker is private local state, never Git. Repeat after OS/recorder changes.
A build or mocked probe does not pass this runtime gate. Also test interactive
area cancellation separately. Screen capture permissions may require restarting
the invoking terminal after consent.

## Acceptance after reviewed-main activation

Test integrated and external keyboards with US and Spanish layouts: Caps Lock,
AltGr symbols, copy/paste/cut/undo/redo, save/find and browser tabs. Test VSCode
editor, input fields and integrated terminal separately; Ctrl+C/Z/D and Neovim/
SSH controls must remain available. Unknown apps and Orca retain their controls.

Test native Mac shortcut precedence, menu keys/cancellation, moving and resizing
with visible indicators, all ten workspaces and graceful app quit. Test captures
on multiple monitors and Retina at different scales, clipboard/file destinations,
visual/explicit regions and cancellation. Test one-session recording, duplicate
start, repeated stop, playable video with system sound, explicit microphone and
no accidental microphone use. Check Linux session/seat changes and remote input.

Native unit checks use simulated desktop/recorder commands and do not record
private windows. Linux evaluation on a Mac is not Linux runtime acceptance.
